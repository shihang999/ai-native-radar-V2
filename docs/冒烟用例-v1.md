# 冒烟用例 v1.0 — AI 推荐录入三模式（9 组核心 case）

> 覆盖 3 种模式 × 3 类结果（正常 / 异常兜底 / 批量边界），共 9 组。
> 每组都写明**前置条件 / 操作步骤 / 期望 / 观察点**，研发自测 + QA 过场通跑即可。

---

## 📝 Case 1：文本解析成功（2 本书 + 不同领域）

**前置**：DashScope Key 有效、Ratelimit 充裕。

**步骤**：
1. 首页点击「推荐一本书」打开抽屉。
2. 选择「粘贴文本」，输入以下内容：
   ```
   团队新人入门先看《深度学习入门》（斋藤康毅）- AI 基础领域 入门阶段 5星，讲得通俗；
   做产品落地可以再读《AI 产品经理实战》，产品应用领域 进阶 4星，对工作流写得很细。
   ```
3. 点击「AI 解析并预览」。
4. 在预览页：
   - 第一本把领域确认是「AI 基础」，阶段「入门」；
   - 第二本把领域确认是「产品应用」，阶段「进阶」；
5. 推荐人填 `匿名测试员`，点击「确认提交」。

**期望**：
- 预览页**拆出 2 张卡片**，标题 / 作者 / 领域 / 阶段 / 理由大体对应。
- 提交成功态文案显示「已收到你的推荐」；成功后 `vw_pending_recommendations` 能看到 2 行。
- `input_mode=text, source=ai_parsed, recommender_name_submitted='匿名测试员'`。

---

## 📝 Case 2：文本解析失败兜底（空 JSON / 广告垃圾）

**步骤**：
1. 粘贴文本：`今天天气真好呀 哈哈哈哈哈哈 无语`（重复 10 遍，≈400 字）。
2. 点 AI 解析。

**期望**：
- 接口返回 `parse_status=empty`，前端弹红色提示「没识别出可推荐的资料，请换一种方式录入或直接手工填写」。
- 仍然跳到**预览页**，展示 1 张空白卡片，用户可以从空卡片补全标题+理由后**仍然能提交**。
- 提交成功，DB 写入 `parse_status_hint=parse_empty`，`source=ai_parsed`，`raw_text_snapshot` 记录原输入。

---

## 🖼️ Case 3：图片 Ctrl+V 粘贴 + OCR 成功

**前置**：本地准备 1 张书单截图（书名清晰、至少 2 本书、有领域关键词，例如「机器学习」「Agent」）。

**步骤**：
1. 打开推荐抽屉，焦点在页面，按 Ctrl+V 粘贴那张图。
2. 自动切到「上传图片」模式，右上角缩略图显示出来。
3. 点 AI 解析。

**期望**：
- Parse 成功，`parse_status=success`，DB `ocr_text_snapshot` 字段有非空识别原文。
- 预览页显示 ≥1 张卡片，标题和 OCR 原文有对应；每张卡片底部「原始摘录」点开能看到被截取出来的文字片段。
- 提交后，`vw_ai_parsed_raw_compare` 视图同时显示 `ocr_text_snapshot` 和结构化字段。

---

## 🖼️ Case 4：图片超限（4 张 / 单张 >4MB）

**步骤**：
1. 选图片模式，连续拖 4 张图。
2. 再上传 1 张 >4MB 的 WEBP。

**期望**：
- 页面在 **Parse 前**就阻断：`一次最多解析 3 张图片`；
- 如果用 postman 直连 `/api/ai/parse-recommendation-input` 发第 4 张：
  - HTTP 400，`parse_status=invalid_input`，`error.user_message` 中文可读；
  - 不产生临时落盘文件（临时目录 `os.tmpdir()` 中不应有 jpg/png 残留，若真落需改代码，当前用 buffer 直接处理是合规的）。

---

## 🎙️ Case 5：语音录音 + ASR 占位成功（MVP 阶段）

**前置**：Chrome 浏览器、允许麦克风权限；ALIBABA_CLOUD_ASR_APP_KEY 目前可能仍是 `__TO_BE_FILLED_BY_DEV__`。

**步骤**：
1. 选语音录入，点击「开始录音」。
2. 说：「建议新人入门先看《动手学深度学习》，AI 基础领域，入门，五颗星，理由是代码全开源。」
3. 10 秒后点「停止录音」。
4. 点「AI 解析并预览」。

**期望**：
- 录音时长显示 ≈10 秒，录音按钮能停止并出现 audio 控件回听。
- 由于 ASR 可能仍是 MVP 占位逻辑（`simulateAsrForMvp`）：会返回一段模拟中文转写文本（开发确认），`parse_status=success` 或 `asr_failed` **都 OK**，关键是**失败不会阻塞提交**：用户能跳到预览页补全并成功提交。
- DB `audio_metadata.duration_seconds` 记录 ≈10，`audio_metadata.mime` 为 `audio/webm`。

## 🎙️ Case 6：语音超长（65 秒）

**步骤**：
1. 语音模式，按住录满 60+ 秒。

**期望**：
- 60 秒到点自动停止录音，按钮从红变蓝；
- 点击解析前如果 duration >60：页面阻断「语音超过 60 秒，请重新录制」；
- 直连 API 也是 400，`parse_status=invalid_input`，中文错误消息。

---

## 🛠️ Case 7：旧手工路径 + 去邀请码 + 不查重拒提

**步骤**：
1. 首页点击「推荐一本书」 → 顶部按钮点「我想手工填写」。
2. 填：
   - 资料名称：《深度学习入门》
   - 类型：书籍
   - 领域：AI 基础
   - 阶段：入门
   - 推荐指数：4
   - 推荐理由：理由很充分，测试一条。
3. 提交。
4. 回到首页，用**完全相同的书名/类型/领域**再手工提交一次。

**期望**：
- 第 1 次提交成功；
- 第 2 次提交**不会**因为查重而被拦截（旧逻辑已删除），仍然成功；
- `vw_pending_recommendations` 能看到两条 `status=pending` 的记录，`source=manual`，`recommender_name_submitted` 为空（没填）；
- 重复候选视图 `vw_pending_with_duplicate_candidates` 中这两条会被标记出来，但审核侧完全保留两条。

## 🛠️ Case 8：批量上限 10 条 + 部分字段校验失败

**步骤**：
1. 文本模式粘贴一段包含 12 本书的假数据（标题+理由每本都写）。
2. 点 AI 解析。
3. 在预览页，点击「+ 新增一本空白条目」尝试 12 次。
4. 把其中 1 本的标题清空、另 1 本的领域选空。
5. 点确认提交。

**期望**：
- 解析接口会把 12 本**截断为前 10 本**（后端 schema.ts `MAX_ITEMS = 10`）；
- 预览页「新增空白」达到 10 后按钮 disabled；
- 提交前前端阻断 `第 X 条：请填写资料名称 / 请选择领域` 至少显示前 3 条错误；
- DB 无写入；用户补完后再次提交成功。

---

## 🛡️ Case 9：XSS / 注入 / 推荐人超长

**步骤**：
1. 文本模式输入：
   ```
   推荐《XSS 测试》，AI 基础 入门 4 星，理由是 <script>alert('x')</script> 很强。
   ```
2. 解析后，在预览页：
   - 推荐人填 `测试名字<script>alert(1)</script>`（然后用 ASCII 拼 120 个字）；
   - 理由里补一段 `"><img src=x onerror=alert(1)>`。
3. 提交。
4. 打开 Supabase Dashboard 看这行 `user_recommendations`。

**期望**：
- 提交成功（字段不会被 400 拒）。
- DB 内：
  - `reason` 中的 `<` `>` 被转义（`sanitizeFreeText` 处理）；
  - `recommender_name_submitted` 被截断 ≤ 50 字，且 `<script>` 已转义成 `&lt;script&gt;`；
- 如果在前端详情页展示（没做则跳过），浏览器不会 alert。
