# 书籍推荐 | Feature Brief

## 1. 文档定位

本文档定义「书籍推荐」功能的已确认产品范围、用户旅程、UX 规则和技术约束。

本文档引用并服从：

- `context/system-overview.md`
- `context/ux-design.md`
- `context/tech-design.md`

如本文档与产品总上下文冲突，应优先修正功能理解，不应直接进入实现。

---

## 2. 功能定位

书籍推荐功能允许用户在浏览读书雷达时，提交一本候选书籍推荐。

该推荐的业务含义是：

> 用户提交了一个候选内容信号，系统在当前浏览器本地保存该记录，供用户查看。本推荐不会自动进入正式雷达，也不代表审核通过。

本功能不是：

- 正式书籍发布；
- 自动收录；
- 大众评分；
- 社区动态；
- 评论系统；
- 审核后台；
- 图书购买或导购。

---

## 3. 背景与 Scope

### 3.1 已知背景

- 读书雷达帮助 AI 从业者发现值得阅读的书籍。
- 当前书籍由系统预置。
- 用户暂时没有推荐书籍的能力。
- 本次希望用户可以提交一本书的推荐，并获得明确的处理结果。
- 推荐不会自动进入正式雷达。

### 3.2 本轮要做

本轮需要完成：

- 用户发现推荐能力；
- 用户完成推荐；
- 用户获得成功或失败反馈；
- 用户能查看本地推荐记录；
- 用户能返回原雷达浏览流程。

### 3.3 本轮不做

本轮不实现：

- 账号；
- 真实后端；
- 数据库；
- 审核后台；
- 自动收录；
- 社区；
- 评论；
- 点赞；
- 收藏；
- 购买入口；
- 现有雷达主流程重构。

---

## 4. To-Be Journey

最小可用版本的 To-Be Journey：

1. 浏览雷达；
2. 发起书籍推荐；
3. 填写并校验；
4. 提交推荐；
5. 获得成功或失败反馈；
6. 查看本地推荐记录或返回浏览。

### 4.1 Journey 说明

用户从现有雷达首页进入推荐流程。

推荐流程应是雷达浏览的补充，不应压过雷达主流程。

提交成功后，用户应明确知道：

- 推荐已保存到当前浏览器本地；
- 推荐不会自动进入正式雷达；
- 推荐仍需后续人工判断；
- 可以查看本地推荐记录；
- 可以返回雷达继续浏览。

---

## 5. 业务规则

### 5.1 支持对象

本轮只支持推荐书籍。

不支持：

- 课程；
- 论文；
- 博客；
- 工具；
- 视频；
- 项目；
- 书单集合。

### 5.2 必填字段

推荐表单必须包含：

| 字段 | 规则 |
|---|---|
| 书名 | 必填 |
| 作者 | 必填 |
| 所属领域 | 必选，复用现有 8 个领域 |
| 推荐指数 | 必选，1-5 |
| 推荐理由 | 必填，默认最短 20 个中文字符 |

### 5.3 字段口径

- 所属领域复用 `DOMAINS`。
- 推荐指数复用当前 1-5 推荐强度语义。
- 推荐理由应说明长期价值、适合阶段、认知价值或推荐依据。
- 推荐理由不应只写“好书”“热门”“很多人推荐”。

### 5.4 推荐结果

推荐提交成功后：

- 保存为本地候选推荐记录；
- 不写入 `BOOKS`；
- 不生成雷达点位；
- 不影响默认学习路径；
- 不影响正式推荐理由区；
- 不代表审核通过。

---

## 6. 本地推荐记录

### 6.1 保存口径

采用浏览器本地保存。

规则：

- 使用当前浏览器的 `localStorage`；
- 刷新页面后仍可查看；
- 换浏览器、换设备、清理浏览器数据后不可恢复；
- 不同步到云端；
- 不代表正式收录；
- 不代表审核通过。

### 6.2 记录展示

每条本地推荐记录展示：

- 书名；
- 作者；
- 所属领域；
- 推荐指数；
- 推荐理由；
- 提交时间；
- 状态：本地已保存，待人工判断。

### 6.3 记录排序与管理

- 本地记录按最新提交在前排序。
- 允许重复推荐同一本书。
- 支持清空全部本地推荐记录。
- 清空记录不做二次确认。
- MVP 不做单条删除、编辑、筛选、搜索或重新提交。

## 7. UX 设计规则

### 7.1 承载方式

推荐方案：首页内嵌推荐模块。

不采用：

- 独立推荐页面；
- 弹窗作为主流程；
- Drawer 作为主流程。

原因：

- 当前首页是第一阶段主体验；
- 推荐是浏览雷达后的补充动作；
- 首页内嵌更容易保留用户浏览语境；
- 表单字段较多，弹窗和 Drawer 不利于移动端输入。

### 7.2 推荐入口

首页应提供轻量入口。

入口可以出现在：

- 标题区或雷达说明区；
- 雷达核心内容之后；
- 推荐模块锚点入口。

入口文案应表达“推荐一本书”或“提交候选推荐”。

不得使用：

- 发布；
- 上榜；
- 投稿上墙；
- 热门推荐；
- 立即收录。

### 7.3 页面结构

推荐模块包含：

1. 功能说明；
2. 推荐表单；
3. 成功或失败反馈；
4. 我的本地推荐记录；
5. 返回雷达浏览动作。

桌面端可以使用表单与记录两列布局。  
移动端必须使用单列顺序布局。

### 7.4 状态反馈

成功反馈应说明：

> 已收到你的候选推荐，并保存到本地推荐记录。它不会自动进入正式雷达，后续仍需人工判断。

失败反馈分为：

- 字段校验失败；
- 本地保存失败。

字段错误应贴近对应字段展示。

本地保存失败时，应提示：

> 未能保存到当前浏览器，请检查浏览器存储设置后重试。

### 7.5 后续动作

提交成功后提供：

- 查看本地推荐记录；
- 继续推荐一本；
- 返回雷达浏览。

提交成功后默认清空表单。

## 8. 数据模型与状态

### 8.1 候选推荐类型

新增独立候选推荐类型，不复用正式 `Book`。

原因：

- `Book` 表达正式雷达书籍；
- 用户推荐只是候选记录；
- 复用 `Book` 容易误接入雷达、默认路径或正式内容列表。

建议字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 本地生成的唯一 ID |
| `title` | string | 书名 |
| `author` | string | 作者 |
| `domainId` | string | 复用现有领域 ID |
| `rating` | 1-5 | 推荐指数 |
| `reason` | string | 推荐理由 |
| `status` | `"local_saved"` | 本地已保存，待人工判断 |
| `createdAt` | string | ISO 时间字符串 |

不包含：

- `ringId`；
- 审核流转状态；
- 推荐人身份；
- 是否进入雷达字段。

### 8.2 页面状态

最小必要状态：

| 状态 | 用途 |
|---|---|
| `formValues` | 当前表单输入 |
| `fieldErrors` | 字段级校验错误 |
| `submitStatus` | idle / submitting / success / error |
| `submitMessage` | 成功或失败反馈文案 |
| `recommendations` | 本地推荐记录 |
| `storageAvailable` | 浏览器本地存储是否可用 |

### 8.3 数据状态规则

- 表单输入未提交前只存在内存中。
- 提交成功后写入 `localStorage`。
- 页面加载后从 `localStorage` 恢复记录。
- 清空记录只清空本地推荐记录。
- 推荐记录不参与雷达渲染。

## 9. 数据访问约束

### 9.1 不新增真实接口

本轮不新增：

- API route；
- server action；
- 数据库访问；
- CMS 访问；
- 远程提交；
- 后端审核。

### 9.2 本地存储能力

新增浏览器端 storage helper，隔离 `localStorage` 读写。

建议能力：

| 能力 | 说明 |
|---|---|
| `loadRecommendations()` | 从 localStorage 读取本地推荐记录 |
| `saveRecommendation(record)` | 追加一条推荐记录 |
| `clearRecommendations()` | 清空全部本地推荐记录 |
| `isStorageAvailable()` | 判断当前浏览器是否允许 localStorage |

localStorage key：

```ts
ai-native-radar:book-recommendations
```

解析失败时，应降级为空记录，并给出本地记录无法读取或无法保存的反馈。

## 10. 组件与复用边界

### 10.1 建议新增组件

| 组件 | 职责 |
|---|---|
| `BookRecommendationSection` | 承载入口说明、表单、反馈、记录列表 |
| `BookRecommendationForm` | 表单输入和校验展示 |
| `RecommendationRecords` | 展示本地推荐记录和清空操作 |
| `SubmitFeedback` | 成功或失败反馈 |

推荐模块应作为 client component。

现有首页可以继续作为页面组合层。

### 10.2 复用

应复用：

- `DOMAINS`；
- `getDomainById`；
- 推荐指数 1-5；
- 首页现有最大宽度、区块节奏、边框和字体；
- `context/ux-design.md` 中的状态视觉语言；
- `context/tech-design.md` 中的静态、低复杂度边界。

### 10.3 不复用

不应复用：

- `Book` 作为候选推荐类型；
- `BOOKS` 作为候选记录存储；
- `RadarChart` 展示候选推荐；
- `LEARNING_PATH` 表达候选推荐。

## 11. 异常与边界情况

| 场景 | 处理方式 |
|---|---|
| 书名为空 | 阻止提交，提示请输入书名 |
| 作者为空 | 阻止提交，提示请输入作者 |
| 未选领域 | 阻止提交，提示请选择所属领域 |
| 未选推荐指数 | 阻止提交，提示请选择推荐指数 |
| 推荐理由为空 | 阻止提交，提示请说明推荐理由 |
| 推荐理由过短 | 阻止提交，提示至少补充 20 个中文字符 |
| localStorage 不可用 | 表单可填写，但提交时提示无法保存到当前浏览器 |
| localStorage 数据损坏 | 忽略损坏数据，显示空记录或提示本地记录无法读取 |
| 重复书籍 | 允许提交，不做去重 |
| 刷新页面 | 本地记录应恢复 |
| 换浏览器或换设备 | 记录不可见，页面需提前说明 |
| 清空记录 | 清空全部本地记录，不做二次确认 |
| 提交成功后 | 清空表单，新记录显示在记录区顶部 |

## 13. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 候选记录被误认为正式内容 | 所有文案使用“候选推荐 / 本地记录 / 待人工判断” |
| localStorage 被误认为云端保存 | 记录区明确“仅保存在当前浏览器” |
| 首页组件继续膨胀 | 推荐逻辑放入独立 client 组件 |
| 表单压过雷达主流程 | 推荐模块放在雷达和核心解释之后，入口轻量化 |
| 推荐功能变成社区感 | 不展示头像、昵称、点赞、评论或公开动态 |

---

## 14. 最小可用版本验收标准

最小可用版本必须满足：

- 用户能从首页发现“推荐一本书”入口；
- 用户能填写书名、作者、领域、推荐指数、推荐理由；
- 空字段和无效推荐理由会被阻止并显示明确错误；
- 提交成功后显示候选推荐已保存到本地；
- 刷新页面后仍能看到本地推荐记录；
- 推荐记录显示书名、作者、领域、推荐指数、推荐理由、提交时间和状态；
- 用户能清空本地推荐记录；
- 推荐不会出现在雷达中；
- 不修改 `BOOKS`、`RadarChart`、`LEARNING_PATH` 的正式数据流；
- 桌面端和移动端都能完成提交与查看记录；
- `npm run build` 通过。
