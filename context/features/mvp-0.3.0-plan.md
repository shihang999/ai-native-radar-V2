## 一、迭代目标与范围

### 1.1 核心目标

将产品从"单页演示原型"升级为"多页面可运营的 Web 应用"，实现完整的用户旅程：
- 用户查看雷达主页，理解认知地图结构
- 用户浏览榜单/书单页，发现优质内容
- 用户查看资源详情，获取完整信息和学习路径
- 用户在任意页面提交推荐，参与共建

### 1.2 本阶段完成

| 功能模块 | 核心价值 | 优先级 |
|---------|---------|-------|
| **多页面架构重构** | 解决单页堆砌问题，提升可扩展性 | P0 |
| **首页雷达主视觉优化** | 强化核心价值，提升专业感 | P0 |
| **书单/榜单页** | 提供快速入口和深度探索 | P0 |
| **资源详情页** | 提供完整信息和学习路径 | P0 |
| **全局推荐入口** | 降低推荐成本，提升共建参与度 | P0 |
| **雷达点位缩略图** | 提升雷达可读性和吸引力 | P1 |
| **Supabase 数据库接入** | 从演示到真实数据驱动 | P0 |

### 1.3 本阶段暂不做

- ❌ 搜索功能（等待用户需求验证）
- ❌ iCloud 式气泡轮转动效（复杂度高，作为增强项）
- ❌ 审核后台（使用 Supabase Dashboard 替代）
- ❌ 个性化推荐
- ❌ 用户收藏、历史记录
- ❌ 评论和读书笔记功能

## 二、页面架构设计

### 2.1 整体架构

采用 Next.js App Router 的多页面架构：

```
/                           # 首页（雷达主页）
/books                      # 书单/榜单页
/books/[id]                 # 资源详情页
/about                      # 关于页（可选）
```

### 2.2 全局导航栏

**桌面端导航结构**：
```
┌──────────────────────────────────────────────────────────────┐
│  [Logo] AI-Native 读书雷达  │ 雷达 | 书单 | 关于  │ [推荐一本书] │
└──────────────────────────────────────────────────────────────┘
```

**移动端导航结构**：
```
┌──────────────────────────────┐
│  [Logo]  AI-Native 读书雷达  │ [☰]
└──────────────────────────────┘
（汉堡菜单：雷达、书单、关于、推荐一本书）
```

**导航项说明**：

| 导航项 | 路由 | 职责 |
|-------|------|------|
| **雷达** | `/` | 展示雷达主视觉、学习路径、领域说明 |
| **书单** | `/books` | 展示榜单卡片和完整书单列表 |
| **关于** | `/about` | 产品说明、价值观、共建规则（可选） |
| **推荐一本书** | - | 全局 CTA 按钮，触发推荐抽屉 |

### 2.3 全局浮动推荐按钮

**位置**：
- 桌面端：右下角固定位置，距离底部 80px，距离右侧 24px
- 移动端：底部居中，距离底部 16px

**样式**：
- 桌面端：圆形按钮，直径 56px，主题色背景
- 移动端：胶囊按钮，高度 48px

**交互**：
- 点击打开推荐抽屉
- Hover 时显示 Tooltip："推荐一本书"

### 3.1 页面职责

让用户快速理解产品定位，看清雷达结构，找到学习起点。

### 3.2 信息架构

```

│   ├── 副标题：产品一句话定义

├── 雷达主视觉区（核心区，占 8+4 列）
│   ├── 左侧：雷达图（占 8 列）
│   │   ├── 领域扇区（8个领域）
│   │   ├── 学习圈层（入门/进阶/高级）
│   │   ├── 资源点位（普通点 + 重点书缩略图）
│   │   └── 交互：悬停 Tooltip、点击跳转详情
│   │
│   └── 右侧信息栏（占 4 列）
│       ├── 如何读这张雷达（颜色、圈层、点、透明度说明）
│       └── 学习阶段（入门/进阶/高级）
│
├── 默认学习路径（可选，默认折叠）
│   ├── 折叠按钮："查看默认学习路径"

    ├── 折叠按钮："查看领域分类"
    └── 展开后：8个领域卡片
```

### 3.3 核心交互设计

#### 3.3.1 雷达点位交互

| 交互类型 | 触发条件 | 视觉反馈 | 数据展示 |
|---------|---------|---------|---------|
| **悬停** | 鼠标移入点位 | 点位放大 10%，边框高亮 | 显示 Tooltip（书名、领域、推荐指数、推荐理由摘要） |
| **点击** | 点击点位 | 无特殊反馈 | 跳转至资源详情页 `/books/[id]` |
| **领域筛选** | 点击右侧领域标签 | 对应扇区高亮，其他淡化 | 雷达图仅显示该领域点位 |
| **圈层筛选** | 点击圈层标签 | 对应圈层高亮，其他淡化 | 雷达图仅显示该圈层点位 |

#### 3.3.2 重点书缩略图气泡（iCloud 风格）

**设计原则**：
- 每个领域仅展示 4-5 本重点书（推荐指数 Top 4-5）
- 其余资源保持普通圆点（直径 8px，领域色填充）

**缩略图气泡样式**：
- 形状：圆形裁切
- 尺寸：直径 40px
- 投影：`0 4px 12px rgba(16, 33, 62, 0.15)`
- 边框：默认无边框，高亮时 2px 实线 `#5DB2E2`

**动效规则**（Phase 2 实现）：
- 漂浮范围：以原始位置为圆心，半径 ≤ 20px
- 高亮节奏：系统按固定节奏（3-5s）轮流高亮重点书
- 交互优先级：用户 Hover/Click 时暂停轮转
- 禁止：自由乱飞、高频跳动、脱离领域扇区

**降级方案**：
- 如无封面图，降级为领域色圆点（保持一致性）

### 3.4 Tooltip 设计

**触发时机**：鼠标悬停 300ms 后显示，避免误触

**信息结构**：
```html
<div class="tooltip" style="max-width: 240px;">
  <h4 class="tooltip-title">书名</h4>
  <div class="tooltip-meta">
    <span class="tooltip-domain">领域标签</span>
    <span class="tooltip-rating">推荐指数: ★★★★☆</span>
  </div>
  <p class="tooltip-reason">推荐理由摘要（不超过 50 字）...</p>
</div>
```

**样式规范**：
- 背景：`#FFFFFF`
- 投影：`0 8px 24px rgba(16, 33, 62, 0.12)`
- 边框：`1px solid #E2E8F0`
- 内边距：12px
- 字体：MiSans, 14px, 行高 1.5

提供完整的书籍信息、推荐理由、用户评分和学习路径指引。

### 5.2 信息架构

```
资源详情页 (/books/[id])
├── 基础信息区
│   ├── 封面大图（左侧，占 4 列）
│   └── 元信息（右侧，占 8 列）
│       ├── 书名（H1）
│       ├── 作者
│       ├── 出版社 | 出版年份
│       ├── ISBN
│       └── 资料链接（课程/文章类型）
│
├── 推荐信息区
│   ├── 推荐指数：★★★★☆
│   ├── 推荐理由
│   ├── 推荐人（如有）
│   └── 标签：[领域] [圈层] [类型]
│
├── 用户交互区
│   ├── 用户评分（1-5 星）
│   ├── 浏览次数
│   └── 收藏按钮（Phase 2）
│
├── 学习路径指引
│   ├── 前置知识（如有）
│   │   └── 推荐前置书籍卡片
│   └── 下一步推荐
│       └── 推荐后续书籍卡片
│
└── 返回按钮
    └── "返回雷达" → 跳转至首页
```

### 5.3 评分交互设计

#### 5.3.1 评分流程

```
用户访问详情页
  ↓
检查是否已评分（通过 session_id）
  ├─ 已评分：显示"已评分: ★★★★☆"，不可修改
  └─ 未评分：显示"点击评分"，引导用户评分
      ↓
  用户点击星星
      ↓
  弹出确认："确认评分为 X 星？"
      ↓
  用户确认
      ↓
  提交评分至 ratings 表
      ↓
  显示成功提示："感谢你的评分"
```

#### 5.3.2 匿名机制

- **标识方式**：使用 `session_id`（浏览器 localStorage 随机生成）
- **防重复**：`UNIQUE (resource_id, session_id)` 约束
- **无需登录**：完全匿名参与

#### 5.3.3 评分限制

- 每个匿名用户对同一资源只能评分一次
- 评分后不可修改

#### 6.2.2 表单验证规则

| 字段 | 验证规则 | 错误提示 |
|-----|---------|---------|
| **资料名称** | 必填，长度 1-255 字符 | "请输入资料名称" |
| **资料类型** | 必填，单选 | "请选择资料类型" |
| **资料链接** | 课程/文章必填，URL 格式 | "请输入有效的资料链接" |
| **领域** | 必填，单选 | "请选择所属领域" |
| **学习阶段** | 必填，单选 | "请选择学习阶段" |
| **推荐指数** | 必填，1-5 星 | "请选择推荐指数" |
| **推荐理由** | 必填，最少 20 字，最多 500 字 | "推荐理由至少需要 20 字" |
| **推荐人** | 可选，长度 1-100 字符 | - |

#### 6.2.3 邀请码验证流程

```
用户填写完表单
  ↓
点击"提交推荐"
  ↓
弹出邀请码输入框（默认隐藏）
  ↓
用户输入邀请码（默认值：1234）
  ↓
前端验证邀请码格式（4位数字）
  ↓
提交至后端 API: POST /api/recommendations
  ↓
后端二次验证邀请码（查询 invite_codes 表）
  ├─ 验证失败：返回错误"邀请码无效或已失效"
  └─ 验证成功：继续
      ↓
  检查重复推荐（查询 resources 和 user_recommendations 表）
      ├─ 重复：返回 { duplicate: true, existing_resource: {...} }
      │    └─ 提示："该资料已被推荐，查看已有推荐"
      └─ 不重复：创建推荐记录
           ↓
       插入 user_recommendations 表（status='pending'）
           ↓
       返回成功："已收到你的推荐，等待管理员审核"
```

### 6.3 推荐成功反馈

## 七、数据流与状态管理

### 7.1 数据流架构

```
用户交互（前端）
  ↓
API 请求（Fetch/Axios）
  ↓
Supabase PostgREST API
  ↓
PostgreSQL 数据库
  ↓
返回数据（JSON）
  ↓
React 组件渲染
```

### 7.2 状态管理策略

**当前阶段**：无需引入全局状态管理库（Redux/Zustand）

**状态管理方式**：
- **服务端状态**：使用 React Query（@tanstack/react-query）
  - 缓存 GET 请求结果
  - 自动重新获取和失效处理
- **客户端状态**：使用 React useState/useReducer
  - 表单状态
  - UI 交互状态（如抽屉开关）
- **URL 状态**：使用 Next.js 路由
  - 推荐抽屉：`?action=recommend`
  - 筛选条件：`?domain=ai-engineering&ring=beginner`

### 7.3 React Query 配置

```typescript
// src/lib/react-query.ts
import { QueryClient } from '@tanstack/react-query';

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000, // 5分钟
      cacheTime: 10 * 60 * 1000, // 10分钟
      refetchOnWindowFocus: false,
    },
  },
});
```

### 7.4 API 缓存策略

| 数据类型 | 缓存时长 | 更新策略 |
|---------|---------|---------|

## 十一、风险与对策

| 风险 | 影响 | 概率 | 对策 |
|-----|------|------|------|
| **榜单数据不足** | 影响书单页展示 | 高 | 冷启动规则：数据不足不展示对应卡片 |
| **推荐入口打扰用户** | 影响阅读体验 | 中 | 桌面端：右下角小浮动按钮；移动端：底部轻量按钮 |
| **缩略图性能问题** | 雷达图加载慢 | 中 | 图片懒加载 + 预加载重点书封面 + CDN 加速 |
| **邀请码泄露** | 恶意刷推荐 | 低 | IP 限制（每小时最多 5 次）+ 后端二次验证 |
| **Supabase 服务不稳定** | 影响数据获取 | 低 | 使用 React Query 缓存 + 错误重试机制 |
| **用户评分刷量** | 影响加权评分准确性 | 中 | 限制同一 IP 评分频率 + 异常检测 |
