# AI-Native 读书雷达 | Tech Design

## 1. 文档定位

本文档定义「AI-Native 读书雷达」当前阶段的工程实现规格。

它负责回答：

- 当前使用什么技术栈；
- 页面、组件、数据和样式如何组织；
- 核心类型和业务数据如何维护；
- 雷达图如何由数据生成；
- 本阶段哪些技术能力明确不做；
- 每次修改后如何验证实现正确。

本文档不负责定义产品目标、用户旅程、视觉风格或内容筛选标准。上述内容分别以 `context/system-overview.md` 和 `context/ux-design.md` 为准。

如本文档与产品总上下文冲突，应优先修正技术实现，不应让工程便利反向决定产品方向。

---

## 2. 当前技术栈

当前项目是一个基于 Next.js App Router 的前端静态应用。

已确认技术栈：

- Next.js `15.x`
- React `19.x`
- TypeScript
- Tailwind CSS `4.x`
- SVG 雷达图
- 本地静态 TypeScript 数据

当前不使用：

- 数据库；
- 服务端接口；
- CMS；
- 用户登录；
- 客户端状态管理库；
- UI 组件库；
- 图表库；
- 后台管理系统。

第一阶段应继续保持静态、可构建、低复杂度。

## 3. 工程结构

当前主要目录职责如下：

| 路径 | 职责 |
|---|---|
| `src/app/layout.tsx` | 全站 HTML 结构和 metadata |
| `src/app/page.tsx` | 首页主体验，承载产品说明、雷达、读图说明、默认路径和推荐理由 |
| `src/app/globals.css` | 全局 Tailwind 引入、主题色变量、字体和基础排版 |
| `src/components/radar/` | 雷达图 SVG 子组件 |

| `src/data/books.ts` | 当前样例书籍数据 |

| `context/ux-design.md` | 视觉与交互规范 |

当前只有一个正式页面路由：`/`。

除非有明确迭代目标，不应新增路由、接口目录、后台目录或复杂状态层。

## 4. 数据模型与数据来源

### 4.1 数据来源

当前所有业务数据来自本地 TypeScript 文件：

- 领域、圈层、路径、雷达配置：`src/lib/constants.ts`
- 书籍样例：`src/data/books.ts`

本阶段不接入远程数据。

不得在组件中硬编码与业务含义强相关的数据，例如领域列表、学习阶段、默认路径或推荐指数映射。这些内容应优先放在 `constants.ts` 或明确的数据文件中。

### 4.2 核心类型

当前核心类型包括：

- `Book`
- `Domain`
- `RingDefinition`
- `LearningPathStep`

`Book` 必须保留以下字段：

- `id`
- `title`
- `author`
- `domainId`
- `ringId`
- `rating`
- `reason`

`domainId` 必须能在 `DOMAINS` 中找到对应项。  
`ringId` 必须能在 `RINGS` 中找到对应项。  
`LearningPathStep.bookIds` 必须引用 `BOOKS` 中真实存在的书籍。

### 4.3 推荐指数

`rating` 当前是 1 到 5 的整数，表达当前样例内容中的推荐强度。

推荐指数只通过透明度和数字展示表达，不作为榜单排序依据，不引入大众评分语义。

## 5. 雷达图实现规则

### 5.1 SVG 结构

雷达图使用原生 SVG 实现，不引入图表库。

组件拆分如下：

- `RadarChart`：组合 SVG、圈层、扇区、标签和书籍点；
- `Ring`：绘制学习阶段圈层；
- `RingLabel`：绘制圈层标签；
- `SectorLine`：绘制领域分隔线；
- `SectorLabel`：绘制领域标签；
- `Blip`：绘制书籍点位。

`RadarChart` 只负责组合，不应承担业务文案、路径卡片或详情列表。

### 5.2 视觉变量含义

雷达图必须保持以下业务含义：

| 视觉变量 | 业务含义 |
|---|---|
| 扇区 / 角度 | 知识领域 |
| 圈层 / 半径 | 学习阶段 |
| 点 | 代表性书籍 |
| 点颜色 | 所属领域 |
| 点透明度 | 推荐强度 |

同一个视觉变量不得同时表达多个冲突含义。

### 5.3 点位计算

书籍点位由 `domainId` 和 `ringId` 决定基础位置。

当前 `Blip` 使用书籍 `id` 做确定性偏移，避免同一扇区和圈层的点完全重叠。

实现要求：

- 同一本书刷新后位置应稳定；
- 点位不得随机变化；
- 点位不得脱离所属领域扇区和学习阶段圈层；
- 缺失领域或圈层时，应使用中性色降级显示，而不是导致页面崩溃。

## 6. 页面实现规则

首页 `/` 是当前第一阶段主体验。

首页必须保持以下信息层级：

1. 产品定位：说明这是 AI 学习认知地图，不是普通书单；
2. 雷达主体：展示领域、阶段和书籍点；
3. 读图说明：解释颜色、圈层、点和透明度；
4. 默认学习路径：回答从哪里开始、下一步学什么；
5. 推荐理由：展示代表性书籍为什么被推荐；
6. 领域假设：说明当前分类仍可验证和调整。

不得在第一阶段加入：

- 登录注册；
- 收藏；
- 用户评分；
- 评论；
- 购买入口；
- 个性化问卷；
- 自动推荐算法；
- 专家后台；
- 内容运营后台。

页面文案必须承认当前内容是“初版样例 / 持续维护中”，不得暗示已经完成正式专家治理。

## 7. 样式与交互规则

视觉和交互以 `context/ux-design.md` 为准。

工程实现上应遵循：

- 使用 Tailwind utility class 进行页面布局；
- 全局颜色变量集中在 `src/app/globals.css`；
- 领域色在 `constants.ts` 和 `ux-design.md` 中保持一致；
- 不使用装饰性渐变、发光、卡通化元素或电商式标签；
- 页面内容最大宽度控制在可读范围内；
- 移动端应保持顺序阅读，不应依赖复杂 hover 才能理解核心信息。

当前 SVG `<title>` 只作为最低限度 hover 信息，不等同于正式 Tooltip 组件。

如后续实现正式 Tooltip，应遵循 `ux-design.md` 中的内容结构和视觉规则。

---

## 8. 可访问性与降级

当前最低要求：

- 雷达 SVG 必须保留 `role="img"` 和明确 `aria-label`；
- 关键推荐理由必须在页面文本中可见，不能只存在于 hover；
- 颜色信息必须配合文字标签使用；
- 页面在没有 JS 交互增强时仍应能阅读核心内容；
- 移动端不能因为雷达缩放导致主要文案不可读。

当前不要求实现完整键盘选中态、屏幕阅读器逐点浏览或复杂交互焦点管理。

## 9. 变更边界

### 9.1 可以做

- 增加本地静态数据字段；
- 增加展示型组件；
- 调整首页信息层级；
- 优化雷达标签、说明和推荐理由展示；
- 增强类型约束和数据一致性检查；
- 补充文档。

### 9.2 暂不做

- 远程接口；
- 数据库；
- 认证；
- 用户行为数据；
- 个性化推荐；
- 复杂筛选；
- 多页面信息架构；
- 后台管理；
- 自动内容审核；
- 大众评分系统。

如确实需要突破以上边界，应先更新 `system-overview.md` 和本文档，再实现。

## 10. 验证方式

每次实现修改后至少执行：

```bash
npm run build
```

提交前应确认：

- 构建通过；
- 首页 `/` 可打开；
- Git diff 只包含本次目标相关文件；
- 没有无关格式化或依赖变更；
- 领域 ID、书籍 `domainId`、圈层 `ringId`、路径 `bookIds` 能对应成功；
- 页面仍能回答“这是什么、怎么读、从哪里开始、下一步读什么、为什么推荐”。

如修改雷达图，应人工检查：

- 扇区标签是否可读；
- 圈层标签是否可读；
- 点位没有明显溢出；
- 移动端雷达没有压缩到不可辨认；
- 推荐理由不只依赖 hover。

## 11. Git 与版本规则

当前项目应保持小步提交。

建议提交信息使用 Conventional Commit：

- `feat:` 新增用户可感知能力；
- `fix:` 修复错误；
- `docs:` 只改文档；
- `refactor:` 不改变行为的结构调整；
- `chore:` 工程配置或维护工作。

涉及产品体验的提交，应在提交前完成构建验证。
